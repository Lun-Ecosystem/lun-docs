# J0 Socle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** poser le socle du MVP : stack et contrat satellite normés, registre étendu et rempli,
monorepo privé `lun-anima` créé et outillé, website intégré à l'écosystème et branché sur le registre.

**Architecture:** lun-docs reste la source des normes (standards, ADR, gabarits, registre). Les
nouveaux dépôts partent du gabarit `templates/project/` plus une surcouche TypeScript
`templates/ts/`. `lun-anima` est un monorepo (workspaces npm) qui accueillera `core/`, `ui/`,
`desktop/` et `mobile/` ; J0 n'y crée que `core/`. Le website lit `registry.yaml` au build et ne
garde que la présentation.

**Tech Stack:** Node ≥ 22, TypeScript strict, Vitest, ESLint, Prettier ; outillage lun-docs sans
dépendance (node:test) ; Astro pour le website ; GitHub (`gh`), Projects v2, Vercel.

**Spec:** `docs/specs/2026-10-19-ecosysteme-design.md` (§3, §4, §6, §9, §10.3 J0).

## Global Constraints

- Tous les dépôts dans l'organisation `Lun-Ecosystem` ; publics sauf `lun-anima` et `website`.
  Un dépôt privé (plan gratuit) n'a pas de ruleset : hook `pre-push` + permissions Claude Code.
- Aucune adresse interne (IP du NAS, Tailscale, domaines privés) ni secret dans un dépôt public.
- Un chantier = une issue + une branche partie de `main` à jour + une PR ; seul CrOliX merge ; jamais
  de push vers `main`, de push forcé, de tag ni de release par l'agent.
- Code, commits et noms techniques en anglais ; docs, issues et PR en français.
- Standards ≤ 150 lignes, ADR ≤ 60 lignes avec une ligne `Statut : acceptée`, CLAUDE.md ≤ 100 lignes.
- `npm test`, `npm run check` et `npm run sync:check` verts dans lun-docs avant chaque PR.
- Versions des dépendances : dernières stables au moment de l'exécution, figées par le lockfile.

## Review Focus

1. Registre injoignable au build du website (réseau, panne GitHub) : le build échoue avec un message
   qui nomme la source ; jamais de site publié vide ou périmé en silence. → test en Task 6.
2. Identifiant du website sans entrée dans le registre (faute de frappe) : le build échoue, sauf pour
   les emplacements « teaser ». → test en Task 6.
3. Un projet mis en réserve (Lun'Avaritia) : affiché en teaser, sans lien ni statut hérité de
   l'ancien dépôt. → test en Task 6.
4. Dépôt privé dans le registre : aucun lien GitHub rendu sur le site. → test en Task 6.
5. Une adresse interne dans un dépôt public créé depuis le gabarit : la CI échoue. → test en Task 2.

### Task 3: Standard du contrat satellite

**Files:**
- Create : `standards/contrat-satellite.md`, `adr/0003-contrat-satellite.md`
- Modify : `tools/standards-map.json` (ajout à `lun-ecosysteme`), `tools/check-repo.mjs`
  (REQUIRED_FILES), `standards/essentiel.md` (un renvoi)

**Interfaces:**
- Produces : le contrat v1, consommé par J1 (Acedia) et J2 (core). Toutes les routes sont sous
  `/lun/v1`, en JSON, authentifiées par `Authorization: Bearer <jeton>` sauf `pair` :

| Route | Rôle | Réponse |
|---|---|---|
| `POST /lun/v1/pair` `{ code }` | échange un code d'appairage (affiché par le satellite, usage unique, 10 min) contre un jeton | `{ token, satellite: { id, nom, version } }` |
| `GET /lun/v1/health` | santé et état | `{ status: 'ok' \| 'paused' \| 'degraded', reason?, version }` |
| `GET /lun/v1/costs?since=<ISO>` | dépense depuis une date | `{ currency: 'USD', since, until, total, items: [{ provider, model?, amount, calls }] }` |
| `POST /lun/v1/pause` `{ reason? }`, `POST /lun/v1/resume` | coupe ou rétablit toute action automatique, sans arrêter le service | `{ status }` |
| `GET /lun/v1/events` | flux SSE ; chaque événement `{ id, type, importance: 'info' \| 'normal' \| 'urgent', at, title, data? }` ; reprise par `Last-Event-ID` | flux |
| `GET /lun/v1/actions`, `POST /lun/v1/actions/:name` | actions disponibles (nom, description, schéma d'entrée JSON Schema) et invocation | `{ actions: [...] }`, puis `{ ok, result?, error? }` |

- [ ] **Step 1 : écrire `standards/contrat-satellite.md`** (≤ 150 lignes) : le principe du §3.1 de
  la spec, le tableau ci-dessus, les codes d'erreur (401 jeton invalide, 409 déjà en pause ou déjà
  actif, 404 action inconnue, 503 `degraded`), le sens des niveaux d'importance (le satellite les

  lectures », la règle de versionnement (rupture = `/lun/v2`, v1 maintenue jusqu'à la migration du
  core). Les types TypeScript du contrat sont écrits en bloc dans le standard ; un paquet partagé
  ne sera créé que si J1 et J2 en ont besoin tous les deux. Une section **« Fronts et vues »**
  reprend le principe 7 et le tableau de frontière du §3 de la spec : un satellite qui a un front
  publie ses vues métier en paquet de composants Svelte, versionné avec lui, nommé
  `@lun-ecosystem/<id>-views` ; son front autonome ne connaît que son serveur (aucun réglage « hub »).
- [ ] **Step 2 : écrire l'ADR 0003** : REST + SSE plutôt que WebSocket (flux à sens unique, reprise
  native, proxys) ; jetons d'appairage plutôt que secret partagé.
- [ ] **Step 3 : brancher** le standard dans `standards-map.json` (skill `lun-ecosysteme`), dans
