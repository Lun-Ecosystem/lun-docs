# J1 Acedia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** livrer `lun-acedia`, satellite public qui remplace Gmail, Google Agenda et Google Tasks
au quotidien : synchro double sens, tri des mails avec validation, agenda unifié, contrat satellite
v1, front autonome installable et paquet de vues publié, prouvé sur le compte Google de test.

**Architecture:** nouveau dépôt public `Lun-Ecosystem/lun-acedia`, monorepo à workspaces npm :
`server/` (Node, Hono, `node:sqlite`, API Google en `fetch`), `views/` (paquet Svelte 5
`@lun-ecosystem/lunacedia-views`, qui ne connaît qu'une interface `AcediaClient`) et `app/` (PWA
Vite qui fournit un `AcediaClient` HTTP aux vues). Google est la source de vérité ; la base SQLite
est un cache plus les données propres d'Acedia (rôles des libellés, règles, propositions, exemples,
journal, coûts, événements, clients appairés).

**Tech Stack:** Node `^22.13.0 || >=24`, TypeScript ~6.0.3 strict, Vitest, Hono +
`@hono/node-server`, `node:sqlite`, zod 4 (schémas et JSON Schema des actions),
`@anthropic-ai/sdk` (tri), Svelte 5 + Vite, `@sveltejs/package`, `vite-plugin-pwa`,
`@testing-library/svelte` + jsdom.

**Spec:** `docs/specs/2026-10-19-j1-acedia-design.md` (cahier des attendus) ; contrat :
`standards/contrat-satellite.md` ; design : `standards/design.md` ; spec de l'écosystème
`docs/specs/2026-10-19-ecosysteme-design.md` (§5, §8, §10).

## Global Constraints

- Un chantier = une issue (gabarit chantier, `niveau:*`, jalon `J1 Acedia` dans le Projects) + une
  branche partie de `main` à jour + une PR avec critères et preuves ; seul CrOliX merge ; jamais de
  push vers `main`, de push forcé, de tag, de release ni de publication de paquet par l'agent.
- Dépôt public : aucun secret, aucune adresse mail réelle, aucune adresse interne (IP, Tailscale,
  domaine privé). Configuration par `.env` (ignoré), `.env.example` sans valeur réelle.
- Code, commits et noms techniques en anglais ; docs, issues et PR en français.
- Google est la source de vérité ; jamais de suppression définitive (corbeille seulement).
- Tout ce qui est automatique s'arrête en pause ; tout ce que fait l'agente se fait à la main et
  ce qu'elle fait automatiquement se défait (journal).
- Crédit IA épuisé = `health` `degraded`, règles actives, rien ne plante.
- Contrat v1 tel qu'écrit dans `standards/contrat-satellite.md` : routes, types, codes 400 / 401 /
  404 / 409 / 503, corps d'erreur `{ error }`. Aucune rupture.
- Une vue, un exemplaire : `app/` n'a aucun composant métier propre, tout vient de `views/`.
- Écrans : tokens de `standards/design.md`, monde Lun'Acedia (fond `#070C14`, accent `#3A6080`).
- Développement et preuves sur le **compte Google de test** uniquement.
- Versions : dernières stables à l'exécution, figées par le lockfile ; TypeScript ~6.0.3.

## Review Focus

1. Historique Gmail expiré (`historyId` trop ancien, 404) ou jeton de synchro Agenda invalide (410) :
   resynchro complète silencieuse, pas d'erreur ni de doublon. → tests en Tasks 4 et 8.
2. Mail dans un jeu de caractères non UTF-8 (ISO-8859-1, Windows-1252) ou avec images inline `cid:` :
   texte lisible, images affichées. → test en Task 4.
3. Jeton Google révoqué ou expiré (refresh refusé) : `health` `degraded` avec raison, événement
   `google.reauth`, lectures du cache toujours servies. → test en Task 3.
4. Un même mail traité deux fois (synchro rejouée, redémarrage pendant le tri) : une seule
   proposition, une seule entrée de journal, un seul appel IA. → test en Task 7.
5. Annuler une action automatique alors que le mail a changé depuis dans Gmail (déjà rangé à la main) :
   l'annulation n'écrase pas le geste manuel, elle échoue avec un message clair. → test en Task 6.

### Task 7: Tri par l'IA, seuil et validation

**Files:**
- Create : `server/src/triage/classifier.ts`, `server/src/triage/anthropic.ts`,
  `server/src/triage/examples.ts`, `server/src/triage/pipeline.ts`, `server/src/triage/proposals.ts`.
- Modify : `server/src/triage/routes.ts`, `server/src/gmail/actions.ts` (enregistrer les exemples).
- Test : `server/src/triage/pipeline.test.ts`, `server/src/triage/examples.test.ts`,
  `server/src/triage/anthropic.test.ts`.

**Interfaces:**
- Consumes : `syncGmail().added` (Task 4), gestes (Task 5), rôles, règles, journal (Task 6),
  `recordCost`, `getState`, `setDegraded`, `emitEvent` (Task 2).
- Produces :
  - `interface Classifier { classify(input: ClassifyInput): Promise<Classification> }` ;
    `ClassifyInput { mail: { from; to; subject; date; text: string /* ≤ 4000 caractères */ }; boxes:
    { id; name }[]; tags: { id; name }[]; examples: Example[] }` ;
    `Classification { boxId: string | 'trash' | 'spam' | null; tagIds: string[]; importance:
    'urgent'|'normal'|'info'|'none'; confidence: number /* 0..100 */; usage: { inputTokens; outputTokens } }`.
  - `createAnthropicClassifier({ apiKey, model = 'claude-haiku-5-5' })` : SDK officiel, sortie
    structurée par un outil `classify` au schéma ci-dessus ; erreur de crédit insuffisant →
    `CreditExhaustedError`. Coût = `usage` × table `PRICES` (`server/src/triage/prices.ts`, tarifs
    relevés sur la page officielle à l'exécution, date notée en commentaire).
  - `pickExamples(db, mail, max = 8): Example[]` : même adresse d'abord, puis même domaine, puis les
    plus récents ; un exemple = `{ from; subject; boxId; tagIds }` issu d'un geste humain.
  - `recordExample(db, mail, boxId, tagIds)` : appelé par toute validation, correction ou rangement
    manuel (principe 4 de la spec).
  - Table `proposals(message_id PRIMARY KEY, box_id, tag_ids, importance, confidence, source:
    'rule'|'ai', status: 'pending'|'auto'|'accepted'|'corrected', created_at)`.
  - `triageNew(deps, ids: string[])` : pour chaque id **sans proposition existante** : en pause → rien ;
    règle → rangement + journal `rule`, proposition `auto` ; sinon, si crédit disponible →
    `classify` ; `confidence >= threshold` → rangement + journal `ai`, proposition `auto` ; sinon
    proposition `pending`. Spam : seulement `boxId === 'spam'` **et** `confidence >= 95`, sinon
    proposition `pending`. Étiquette « Urgent » (tag dont le nom normalisé est `urgent`) ajoutée à la
    proposition si `importance === 'urgent'`. Événements : `mail.pending` ou `mail.triaged` avec
    l'importance de la classification (`none` → aucun événement), titre = sujet. Première
