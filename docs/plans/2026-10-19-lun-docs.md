# lun-docs : plan d'implémentation

> **Pour les agents d'exécution :** SKILL OBLIGATOIRE : superpowers:subagent-driven-development (recommandé)
> ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases
> à cocher (`- [ ]`) pour le suivi.

**Objectif :** créer le dépôt public `CrOliX-AltF4/lun-docs` : le référentiel central de l'écosystème Lun'
(vision, standards, ADR, registre, gabarits) et le plugin Claude Code `lun` qui le distribue à chaque projet.

**Architecture :** un dépôt Markdown qui est aussi une marketplace Claude Code (`.claude-plugin/marketplace.json`
à la racine, plugin dans `plugin/`). Un petit outillage Node sans dépendance (`tools/`) vérifie le dépôt
(fichiers requis, longueur des standards, aucune adresse interne, registre, synchronisation standards → plugin)
et un hook du plugin bloque les gestes réservés à CrOliX (merge, push sur `main`, force).

**Stack :** Markdown, YAML, Node ≥ 22 (`node:test`, aucune dépendance runtime), Claude Code 2.1.x
(`claude plugin validate --strict`, `claude plugin details`), GitHub CLI, GitHub Actions.

**Spec :** `docs/specs/2026-10-19-referentiel-design.md` (à lire avant toute tâche ; les § cités renvoient à elle).

## Contraintes globales

- Racine : `D:\projets\projets perso\LunEcosystem\lun-docs\`. Les anciens projets (`D:\projets\projets perso\Lun*`, `website`) se **lisent** mais ne se modifient jamais.
- Dépôt **public**, licence MIT. Aucun secret, aucune adresse interne (IP privées, `100.64.0.0/10`, `*.ts.net`, domaines du NAS). <!-- allow-address -->
- Docs en **français** ; code, noms de fichiers d'outillage, commits en **anglais**.
- Commits : Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `ci:`, `test:`).
- Chaque standard (`standards/*.md`) : **150 lignes max** (traduction de « une à deux pages », §5.2).
- `templates/project/CLAUDE.md` : **100 lignes max** (§5.9).
- Une seule source par information (§5.4) : pas de fichier d'avancement, pas d'historique dans les docs.
- Plugin : nom `lun`, marketplace `lun-docs`, identifiant d'installation `lun@lun-docs`.
- Modèles des agents (§5.8.2) : `dev-haiku` → `haiku`, `dev-sonnet` → `sonnet`, `dev-opus` → `opus`, `dev-fable` → `fable` ; `explorer` → `haiku` ; `reviewer` → `sonnet` ; `plan-challenger` → `opus`.
- Étiquettes : `inbox`, `niveau:trivial`, `niveau:standard`, `niveau:critique`, `niveau:exceptionnel`.
- Git : `main` reçoit le commit initial (la spec et ce plan) ; tout le reste passe par la branche `feat/bootstrap` et une PR que **CrOliX merge**. L'agent ne merge jamais et ne pousse jamais sur `main` après le commit initial.

## Points de vigilance (Review Focus)

1. **Contournements du hook de garde** : `git push origin HEAD:main`, `git push -f`, `--force-with-lease`, `git -C <dir> push`, commandes chaînées (`cd x && git push origin main`), `gh pr merge --auto`. Tous doivent être bloqués (tests en tâche 8).
2. **Windows** : fins de ligne CRLF dans le comptage des lignes, chemins avec espaces (`projets perso`), hook exécuté par `node` et non `bash` (tests en tâches 1 et 8).
3. **Dérive des copies** : une modification faite dans une copie sous `plugin/` au lieu de `standards/` doit faire échouer `sync-standards --check` (test en tâche 9).
4. **Fuite d'adresse interne** dans un dépôt public : IP privée, IP Tailscale, `*.ts.net` (test en tâche 1).
5. **Coût de contexte du plugin** : description de chaque skill ≤ 300 caractères, total projeté relevé par `claude plugin details lun` et noté dans la PR (contrôle en tâche 9).
